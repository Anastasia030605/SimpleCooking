# SimpleCooking

Учебный сайт с рецептами на React + TypeScript. Цель демонстрации 26 октября: создать рецепт → найти в каталоге по времени → открыть → изменить порции → сохранить в избранном → открыть из избранного после перезагрузки.

## Запуск

Нужны Node.js 20+ и npm. В репозитории также есть lockfile для pnpm.

```bash
npm install
npm run dev
```

С pnpm: `pnpm install`, затем `pnpm dev`.

После запуска откройте адрес, напечатанный Vite (обычно `http://localhost:5173`). Проверка сборки: `npm run build`.

Автоматический тест: `npm run test` (или `pnpm test`). Vitest и React Testing Library запускают в jsdom один сценарий: открытие рецепта → увеличение порций и пересчёт ингредиентов → добавление в избранное с сохранением в localStorage. Тест находится в `src/pages/RecipePage.test.tsx`.

## Что уже готово

- React + TypeScript + Vite и маршруты `/recipes`, `/recipes/:id`, `/recipes/new`, `/favorites`.
- Общая шапка, навигация, компоненты `Button`, `Input`, `RecipeCard`.
- Каталог с поиском по названию и фильтром по максимальному **общему** времени (`prepTimeMinutes + cookTimeMinutes`).
- Состояния загрузки, ошибки чтения хранилища и пустой выдачи.
- Общий контракт рецепта и хранилище `localStorage`; новые рецепты появляются в каталоге сразу после `saveRecipe` и остаются после перезагрузки.
- Временные экраны для маршрутов участников 2 и 3 находятся в `src/pages/RoutePlaceholders.tsx`.

## Контракт для команды

Типы `Recipe`, `Ingredient`, `Step`, `User` и тестовый пользователь находятся в `src/domain/recipe.ts`. Каталог использует `Recipe.id`, `title`, `category`, `description`, `prepTimeMinutes`, `cookTimeMinutes`, `baseServings` и `image`. Для пересчёта порций нужны `Ingredient.amount`, `unit` и `Recipe.baseServings`.

Хранилище находится в `src/data/recipeStore.ts`:

```ts
getRecipes(): Recipe[]
getRecipeById(id: string): Recipe | undefined
saveRecipe(recipe: Recipe): void
subscribeToRecipes(listener: () => void): () => void
```

Ключ `localStorage`: `simpleCooking.recipes.v1`. При отсутствии сохранённых данных каталог показывает три примерных рецепта. `saveRecipe` сохраняет новый рецепт вместе с ними и уведомляет каталог в этой вкладке; событие `storage` обновляет другие вкладки. Если браузер не даёт читать или писать хранилище, функция выбрасывает ошибку; интерфейс должен показать её пользователю.

### Участник 2

Создайте страницы рецепта и избранного и замените в `src/app/App.tsx` импорты `RecipePlaceholder` и `FavoritesPlaceholder`. Для чтения рецепта используйте `getRecipeById` либо `useRecipes`. Базовые количества ингредиентов не изменяйте: отображаемое количество = `amount * выбранныеПорции / baseServings`. Для избранного используйте отдельный ключ в `localStorage`, чтобы не менять список рецептов.

### Участник 3

Создайте форму публикации и замените `NewRecipePlaceholder` в `src/app/App.tsx`. После проверки обязательных полей сформируйте `Recipe` с уникальным `id`, `authorId: TEST_USER.id`, датой `createdAt` в ISO-формате и вызовите `saveRecipe(recipe)`. После успешного сохранения переходите на `/recipes/${recipe.id}`. Форма может расширить реализацию хранилища, сохраняя приведённый публичный контракт.

Для публикации нужны название, категория, положительное число порций, хотя бы одно положительное поле времени, минимум один ингредиент и один шаг. Количество ингредиента может быть `null` для формулировок вроде «по вкусу»; при числовом количестве нужна единица измерения. Описание и фотография необязательны. Для содержательной фотографии нужен `alt`.

## Доступность

Есть ссылка пропуска навигации, видимый фокус, подписи полей, текстовые ошибки и семантические элементы. Каждый участник проверяет клавиатуру и увеличение текста на своих новых экранах.
